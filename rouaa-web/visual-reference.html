ROUA Institutional Intelligence Design System · v1.0 FINAL

The unified design, data, and interaction language behind ROUA intelligence infrastructure.

This is not a style guide. It is the operating language of an intelligence institution — surfaces that hold data, intelligence objects that carry provenance, evidence patterns that prove each governed claim, and operational states that reflect how the system actually runs. Every ROUA interface inherits from here.

REF VR-001 SECTIONS 21 STATUS Live
Foundational Principle

ROUA does not optimize for producing more outputs.
It optimizes for producing defensible outputs.

The competition is not speed. The competition is trust. An institution that publishes 50 unverifiable claims has nothing. An institution that publishes 5 claims — each traceable to a source, each carrying its evidence, each defensible under audit — has infrastructure. Every design decision in this system serves that principle.

Type

Fact, Event, Entity, Evidence Package, Scenario, or Forecast. The type determines which fields the object carries.

Provenance

Source ID, document locator, page and section. Every object traces back to a verifiable original. No anonymous intelligence.

Confidence

A defensible score with methodology. Not a vibe. Not a percentage plucked from a model. The method is documented and auditable.

REUSABILITY RULE

One Intelligence Object can be consumed by multiple workflows. The same FOMC Rate Decision object feeds a research brief, a trading workflow, and a risk dashboard — all from one verified source.

Section 16 Enterprise States

The system is not always ideal.

Real institutions run on real data — sources delay, documents are incomplete, confidence drops, humans must review. ROUA does not hide these states behind a green checkmark. Six operational states, each visually distinct, each with a clear next action.

Operational STATE 01
Source healthy, evidence verified

The default state. Source is reachable, document was ingested, fact extracted, evidence chain complete, confidence above threshold. No action required.

Action: none
Processing STATE 02
Document in pipeline

Source fetched, document is being classified, facts extracted, or evidence assembled. The system is working — show progress, not a spinner without context.

Action: wait · ETA shown
Needs Review STATE 03
Confidence below threshold

Confidence score fell below the institutional threshold (e.g. 85%). The output is staged but flagged. A human reviewer must confirm before the intelligence object is published.

Action: reviewer → approve / reject
Source Delayed STATE 04
Scheduled release not yet received

A scheduled release (e.g. CPI at 12:30 UTC) was expected but not yet received. The system continues monitoring and will auto-recover when the source publishes. Surfaces the delay transparently.

Action: monitor · alert after +15m
Evidence Missing STATE 05
Chain broken — cannot verify

The evidence chain cannot be completed — a document was retracted, a source changed its URL, or a fact could not be located. The output is suppressed. ROUA never publishes unverifiable intelligence.

Action: suppress · investigate
Human Validation STATE 06
High-stakes output — analyst required

Reserved for high-stakes intelligence (e.g. rate decisions, M&A confirmations, default events). The system assembled the object but policy requires a human analyst to sign off before publication. The gold border signals verified-after-review.

Action: analyst sign-off required
State Transition Rules

Every state change is logged, timestamped, and attributable. An object can move Operational → Processing → Operational as it is re-processed, or Operational → Needs Review → Human Validation → Operational when confidence drops. The transition history is part of the object's provenance — auditors can reconstruct exactly when and why the state changed.

Section 17 Human Oversight Layer

The human is part of the system.

Investment committees and regulators do not trust autonomous AI. ROUA does not pretend to be autonomous. Every high-stakes intelligence object passes through a documented human oversight chain before publication. The human is not a fallback — the human is a layer.

01
Automation
System extracts, classifies, and assembles

Source fetched, document parsed, facts extracted, evidence chain assembled, confidence scored. All automated, all logged.

02
Evidence Validation
Chain integrity verified

Source → Document → Fact → Evidence links confirmed. Locator (page, section) re-checked against original.

03
Confidence Assessment
Score compared to threshold

If confidence ≥ 85% and policy allows, object may auto-publish. If below threshold, routed to human review.

04
Human Review
REQUIRED FOR HIGH-STAKES
Analyst signs off, edits, or rejects

A named human reviewer examines the object, confirms the evidence, and either approves, amends, or suppresses. The reviewer's identity is recorded in the object's provenance.

05
Institutional Publication
Object published, immutable, auditable

Once published, the object is versioned and immutable. Every downstream consumer sees the same verified object with the same provenance.

Principle 01
Named, not anonymous

Every human review is attributed to a named analyst. No anonymous approvals. No "the system decided."

Principle 02
Policy-driven, not ad-hoc

Which object types require review is defined by institutional policy — not by the model, not by the analyst, not by the moment.

Principle 03
Auditable after the fact

Three years later, an auditor can reconstruct: who reviewed, when, what they saw, what they decided. The review record is permanent.

Section 18 Usage Guidelines

When to use what — not just what exists.

The system defines colors, surfaces, and components. But a design system is incomplete without rules for when each element is used. Color carries meaning. If an element uses a color, that color must communicate something specific — never decoration.

The Golden Rule

Gold is not decoration.
If an element uses gold, it must communicate trust, importance, or action.

Color Meaning Use For
Gold Verified / Important / Primary Commercial Action Evidence markers, confidence scores, briefing CTA, verified badges
Emerald Operational Success System healthy, completed process, operational status
Amber Attention Required Review needed, pending validation, building state
Red Failure / Risk Broken chain, failed process, evidence missing
Blue Information Neutral system info, supported status, processing
Surface Selection Rules
Surface Card

Use for general data, descriptions, navigation. The default container. If unsure, start here.

Intelligence Object Card

Use ONLY for typed intelligence objects — facts, events, evidence packages. The gold border is earned, not decorative.

Evidence Card

Use when displaying provenance chains. Source → Document → Fact → Evidence, each as a labeled row.

System Panel

Use for operational telemetry, status consoles, queue monitors. Monospace throughout. Reads as data, not design.

Forbidden Patterns
  • Gold used for decoration, dividers, or background fills
  • More than one full-gold button per view (Commercial CTA only)
  • Green used for non-operational elements
  • Red used for anything other than failure or risk
  • Backdrop blur, translucency, or glassmorphism on any surface
  • Gold left border on a card that is not an Intelligence Object

Section 21 Localization Rules

English first. Arabic ready.

ROUA’s operating language is English. Arabic is a supported secondary language for regional institutional contexts. The system is not a bilingual consumer product — it is an institutional intelligence platform with RTL capability. Mirror layouts, not meaning.

Primary
English
LTR · Default

All system labels, evidence IDs, source identifiers, and object types remain in English across all locales. These are operational identifiers, not translatable text.

Secondary
Arabic
RTL · Regional

Available for institutional clients in MENA. Headlines, descriptions, and analyst notes translate. System identifiers do not.

RTL Requirements
Mirror layouts, not meaning

Layout direction flips (left ↔ right). The semantic order of the evidence chain does not — Source always precedes Output.

Maintain evidence hierarchy

The 6-node chain (Source → Document → Fact → Evidence → Object → Output) is read left-to-right in LTR and right-to-left in RTL, but the hierarchy is preserved.

Preserve data identifiers

Evidence IDs (EVT-FOMC-2026-08-001), Source IDs (FED-001), and object types (EVENT, FACT) remain in English and LTR within RTL layouts.

Keep numerical formats unchanged

Confidence scores (97.4%), rates (5.25–5.50%), dates (2026-08-03), and all numeric data remain in international format. Numbers do not localize.

RTL Principle

The system’s priority: System → Application → Translation. A full Arabic version of the Design System is not built now. The rules above ensure that when the time comes, the system is ready — without redesign.
