The Developer Problem

Intelligence is not a model.
It is a pipeline — and most teams cannot build it.

Fintechs, brokers, and data platforms ship products that depend on financial intelligence. The hard part is not the front-end — it is the source ingestion, evidence layer, governance, and audit trail that turn raw data into defensible intelligence.

Years, Not Weeks

Building intelligence pipelines takes years.

Source licensing, ingestion infrastructure, entity resolution, fact extraction, provenance tracking, governance controls, and audit tooling — assembled from scratch, this stack consumes years of engineering time before the first intelligence product ships.

No Evidence Layer

Existing products ship without an evidence layer.

Today's market data, analytics, and news products deliver values, signals, and summaries — but no provenance. A user who asks "where did this come from?" is told to trust the system. That answer fails institutional due diligence and regulator review.

Provenance Failure

Data without provenance fails institutional review.

When a bank, asset manager, or regulator asks for the source behind a number, an answer that points to "our internal model" is rejected. Institutions require traceability to official sources — and products without it never make it past procurement and compliance review.

Capabilities

Four API surfaces. One evidence architecture.

Every capability returns the same evidence layer — sources, paragraphs, confidence, and governance metadata attached to every fact, event, and assertion your application consumes.

01 · Events API

Material events, queryable.

REST and streaming endpoints for verified financial events — monetary policy decisions, earnings, regulatory actions, geopolitical developments. Filter by entity, jurisdiction, event type, confidence tier, and time window. Every event carries its source chain.

02 · Facts API

Structured facts, evidence-linked.

Retrieve verified facts — rates, exposures, sanctions status, ownership structures, entity attributes — each returned with its evidence chain: source document, paragraph, excerpt, extraction confidence, and verification tier. No fact ships without provenance.

03 · Evidence API

Evidence packs, on demand.

Assemble evidence packs for any fact, event, or assertion — sources, extracted clauses, confidence scoring, and governance trail reconstructed for audit, regulatory inquiry, or end-user disclosure. Build "show me the source" into every product surface.

04 · Streaming + SDKs

Real-time streams, typed SDKs.

WebSocket and gRPC streaming for low-latency event delivery, with typed SDKs for TypeScript, Python, and Java — including filters, back-pressure handling, retry semantics, and built-in evidence deserialization. Ship integration in days, not quarters.

Code Example

Five lines to a verified fact.
A few more to a live event stream.

Typed SDKs, evidence attached to every response, and streaming that preserves provenance end-to-end. This is what your integration looks like.

TypeScript — Retrieve a verified fact with its evidence chain
import { RouaaClient } from "@rouaa/sdk";

const rouaa = new RouaaClient({
  apiKey: process.env.ROUAA_API_KEY,
  environment: "production",
});

// Retrieve a verified fact — evidence chain attached by default
const fact = await rouaa.facts.retrieve("FCT-7E3A91", {
  includeEvidence: true,
  includeSources: true,
});

console.log(fact.statement);
// → "ECB raises deposit facility rate by 25 bps to 4.00%."

console.log(fact.confidence, fact.verificationTier);
// → 0.97  "T1 — official primary source"

// Every fact arrives with its full evidence chain
for (const node of fact.evidenceChain) {
  console.log(node.source.uri,    // ecb.europa.eu
              node.paragraph,     // 3
              node.excerpt);      // "The Governing Council decided to raise..."
}
Python — Stream material events with provenance preserved
import os
from rouaa import RouaaClient
from rouaa.streaming import EventFilter

client = RouaaClient(api_key=os.environ["ROUAA_API_KEY"])

# Stream material events as the engine verifies them
stream = client.events.stream(
    filter=EventFilter(
        entity_ids=["LEI:5493001KJTIIGC8Y1R12"],   # ECB
        event_types=["monetary_policy", "rate_decision"],
        min_confidence=0.85,
        tiers=["T1", "T2"],
    )
)

for event in stream:
    print(event.type, event.timestamp.isoformat())
    print(" ", event.payload.summary)

    # Provenance travels with every streamed event
    for source in event.evidence:
        print("    -", source.uri,
              "¶", source.paragraph,
              source.excerpt[:80])

SDKs available for TypeScript, Python, and Java. REST and gRPC endpoints for every other language. Evidence chains are part of the response schema — no separate call, no async reconciliation.

Deployment Models

Deploy where your product requires.

Three deployment models — same API surface, same evidence architecture, same SDKs. Choose by latency, data residency, and the governance profile your customers and regulators expect.

Deployment 01

API

Connect to the hosted ROUAA API over REST, gRPC, and WebSocket — authenticated, rate-limited, and globally distributed. No infrastructure to operate; SDKs handle the rest. Ship integration in days.

Ideal For
Fintechs, brokers, and developers shipping products where hosted latency and multi-region availability are sufficient and data residency constraints are modest.
Deployment 02

Cloud

Dedicated ROUAA environment inside your own cloud tenancy — isolated compute, dedicated capacity, and customer-managed keys. Same API surface as hosted, with tenant isolation and cloud-native controls under your perimeter.

Ideal For
Data platforms and institutions that need tenant isolation, dedicated capacity, and cloud-native controls without operating the full intelligence stack themselves.
Deployment 03

Private Cloud

Full ROUAA intelligence infrastructure deployed inside your data center — complete data sovereignty, evidence provenance, and governance under your direct control, including air-gapped operation and on-premise source ingestion.

Ideal For
Regulated institutions, supervisors, and platforms with strict data residency, sovereignty, or air-gapped requirements — typically banks, systemically important institutions, and sovereign clients.
